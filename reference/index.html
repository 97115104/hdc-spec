AIISP-2 Reference Design

MIT-licensed implementation target for AIISP-2. The active specification and schemas remain normative.

SurfacePurposePrimary requirement
ContractsHDCT token and settlement behavior.Mint once per accepted event and reject duplicate event_id values.
RouterHTTP routing, category selection, node dispatch, and batch writing.Return ordinary model responses while producing auditable AIISP-2 settlement records.
NodeInference-node adapter and manifest behavior.Publish capabilities, serve eligible category models, and sign serving evidence.
ConformanceSchema, routing, duplicate-event, settlement, and privacy checks.Verify implementations against AIISP-2 Draft v0.1 behavior.

Implementation Sequence

  1. Validate examples against the JSON schemas.
  2. Implement POST /v2/inference in the router.
  3. Implement node manifests, health checks, and serving-evidence signatures.
  4. Implement local-chain settlement with duplicate-event rejection.
  5. Add conformance cases for schema validity, routing failures, settlement failures, and privacy redaction.
  6. Run the same conformance suite against a local test chain and then Base Sepolia.
