Reference Router

HTTP boundary for category routing, node dispatch, serving evidence, and batch settlement.

Request Path

  1. Receive POST /v2/inference.
  2. Require X-AIISP-Category.
  3. Validate the request body against the AIISP-2 inference-request schema.
  4. Resolve the category to an eligible model and inference node.
  5. Dispatch the request to the node.
  6. Receive model output and serving evidence.
  7. Create a settlement event and add it to the current settlement batch.
  8. Return an ordinary model-response object with AIISP-2 headers and/or an aiisp response object.

Headers

HeaderDirectionMeaning
X-AIISP-Categoryrequest and responseCategory selected for routing and settlement.
X-AIISP-ModelresponseCategory model served.
X-AIISP-NoderesponseInference node that served the request.
X-AIISP-Settlement-EventresponseEvent identifier for settlement.
X-AIISP-Settlement-BatchresponseBatch identifier containing the event.

Failure Cases

  • aiisp_category_required for missing category.
  • aiisp_category_unknown for unknown category.
  • aiisp_model_not_in_category for a requested model outside the category.
  • aiisp_node_unavailable for unavailable nodes.
  • aiisp_settlement_unavailable for failed settlement.
  • aiisp_policy_rejected for policy rejection.

Privacy Requirement

The router must not write raw prompts, completions, private client identifiers, secrets, or undisclosed contributor data into public settlement records.
